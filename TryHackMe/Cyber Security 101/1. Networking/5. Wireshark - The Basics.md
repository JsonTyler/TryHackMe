- Introduction
	- Wireshark is an open-source, cross-platform network packet analyser tool capable of sniffing and invesetigating live-traffic and inspecting packet captures (PCAP)
	- Commonly used as one of the best known packet analysis tools
- Tool Overview
	- Purposes of use for Wireshark:
		- Detecting and troubleshooting network problems
		- Detecting security anomalies
		- Investigating & learning protocol details
	- It is read-only, no modiciation

	- Colouring Packets
		- Wireshark colours packets in order of different conditions to help spot anomalies quickly
			- You are able to create custom colour rules to spot events as well
		- Has two types of packet colouring methods
			- Temporarily rules that are only available during a program session
			- Permanent rules that are saved under the preference file (profile) & available for the next program session
	- Traffic Sniffing
		- Use the blue "shark button" to start network sniffing (capturing traffic)
		- Use the red button to stop the sniffing
		- Use the green button to re-start the sniffing
	- Merge PCAP Files
		- Has ability to combine 2 pcap files into 1 single file
			- File > Merge
- Packet Dissection
	- Packet dissection is aka protocol dissection which investigates packet details by decoding, available protocols and fields
	- Wireshark supports a long list of protocols for diseection
	- Ability to write your own dissection scripts too
	- Packets in wireshark have 7 distinct layers: 
		- frame/packet, source [MAC], source [IP], protocol, protocol errors, application protocol, and application data
	- Layer 1 - The Frame: 
		- Shows you what frame/packet you are looking at and details specific to the physical layer of the OSI
	- Layer 2 - Source [ MAC] : 
		- Shows you the source and destination MAC Addresses
		- Specific to the data link layer of the OSI
	- Layer 3 - Source [IP] :
		- Shows the source and desination IPv4 Addresses
		- Specific to the network layer of the OSI
	- Layer 4 - Protocol:
		- Shows details of the protocol used (UDP/TCP) and source & destination ports
		- Includes "Protocol Errors" which show specific segments from TCP that need to be reassembled
		- Specific to the transport layer of the OSI
	- Layer 5 - Application Protocol:
		- Shows details specific to the protocol used (http, ftp, and smb)
		- Includes "Application Data" which can show app specific data
		- Specific to the application layer of the OSI
- Packet Nagiation
	- Packet Numbers
		- Wireshark calculates the number of investigated packets and assigns a unique number for each one
			- Helps the analysis process for big captures and makes it easy to go back to a specific point of an event
		- Feature
			- Navigates between packets up and down
			- Provides in frame packet tracking and finds the next packet in the particular part of the onversation
	- Find Packets
		- Edit > Find packet
		- To find a packet:
			- Know the input type (display filter, hex, string, regex)
			- Choosing the search field
	- Mark Packets
		- Ability to find/point to a specific packet for further investigation
		- Edit/Righ-click to mark/unmark packet
		- Marked packets will be show in black
		- Marked packets do not survive session closing
	- Packet Comments
		- Ability to add comments for particular packets that help the investigation or act as a reminder to point out important/sus points for other analysts
		- Commented packets survive session closing until manually removed
	- Export Packets
		- Ability to export out specific packets/pieces that are sus/scoped
		- Use file menu to export
	- Time Display Format
		- Wireshark lists packets as they are captured in "Seconds Since Beginning of Caputre"
		- More common format is UTC Time Display Format
			- View > Time Display Format
- Packet Filtering
	- Two types of filtering approaches
		- 1) Capture filters: used for capturing only the packets valid for the used filter
		- 2) Display filters: used for viewing the packets valid for the used filter
	- Filters are specific queries designed for protocols availble in Wireshark's official protocol reference
	- Apply as Filter
		- Most basic way to filter traffic
		- Click on field you want to filter and right-click (Analyse > Apply as Filter)
	- Conversation Filter
		- Helps you view only the related packets and hide the rest of the packets
		- Right-click menu or Analyse > Converesation filter
	- Colourise Conversation
		- Similar to "Conversation Filter" but instead highlights the linked packets w/o applying a display filter and does not decrease the # of viewed packets
		- Right-click menu or View > Colourise Conversation
		- View > Colourise Conversation > Reset Colourisation
	- Follow Stream
		- Right click menu or Analyse > Follow TCP/UDP/HTTP Stream menu to follow traffic streams
	- Simple Display Filter Queries
		- Easiest way to filter quickly is by applying a display filter using the "Apply a display filter" bar on the top
			- Filter by Protocol Name or Port
			- Filter by IP
