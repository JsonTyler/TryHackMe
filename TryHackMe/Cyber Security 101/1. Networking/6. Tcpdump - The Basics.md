- Introduction: 
	- The Tcpdump toola nd its libpcap library are written in C/C++ and were released for unix like system in 1980/90s
	- Offer optimal speed
	- Libpcap library is the foundation for various other networking tools
		- POrted to ms windows as winpcap
- Basic Packet Capture:
	- Specify the Network Interface:
		- -i INTERFACE (ex: -i eth0 or -i any)
	- Save the Captured Packets
		- -w FILE
		- extension is set most commonly to .pcap
		- saved packets can be inspected later by Wireshark
	- Read Captured Packets from a File
		- -r FILE
	- Limit the Number of Captured Packets
		- -c COUNT
	- Don't Resolve IP Addresses & Port Numbers
		- -n avoids DNS lookups
		- -nn stops both DNS and port number lookups
	- Produce Verbose Output
		- -v (prints time to live, identification, total length, and options in an IP packet)
		- -vv (more verbose output)
		- -vvv (even more verbosity)
- Filtering Expressions:
	- The issue: You can run tcpdump w/ou filtering expressions but would not be useful because of the sheer number returned (Impossible to see everything at once)
	- Filtering by Host:
		- You can limit the captured packets to a specific host using host IP or host HOSTNAME
	- Filtering by Port:
		- You can capture DNS traffic and limit the captured packets to those by port 53
			- DNS uses UDP and TCP ports 53 by default
	- Filtering by Protocol:
		- Ability to limit the packet capture to a specific protofol (ex: ip, ip6, udp, tcp, icmp)
	- Logical Operators
		- `and`: Captures packets where both conditions are true
		- `or`: Captures packets when either one of the conditions is true
		- `not`: Captures packets when the condition is not true
