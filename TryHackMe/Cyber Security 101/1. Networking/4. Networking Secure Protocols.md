- TLS
	- TLS stands for Transport Layer Security and was developed in 1999 by the Internet Engineering Task Force (IETF)
		- TLS upgraded and built upon SSL
	- TLS 1.3 is the most recent & advanced version from 2018
	- Many protocols have received security upgrades with TLS now added
		- Ex: HTTPS, SMTPS, POP3S, IMAPS
	- The 1st step for every server/client that needs to identify itself is to get a signed TLS certificate
		- Once signed it is used to identify itself to others for validity
	- You should not rely on **self-signed certificates** (or any certificate that isn’t validated through a **trusted Certificate Authority (CA) chain**) to confirm a server’s authenticity, because they don’t provide third-party identity assurance and can be trivially used by an attacker in a MITM scenario.
- HTTPS
	- HTTPS stands for Hypertext Transfer Protocol Secure
		- Basically is HTTP over TLS
	- Requires 3 steps after resolving the domain name
		- Establish a TCP 3 way handshake with the target server
		- Establish a TLS session
		- Communicate using the HTTP protocol
	- Adding TLS to HTTP (for HTTPS) leads to all the packets being encryped
		- We can no longer see the contents of the exchanged packets unless we have the private key for access

- SSH
	- When you use SSH today it most likely is OpenSSH an open-source implementation of it from OpenBSD devs
		- Several benefits:
			- Secure authentication
			- Confidentiality
			- Integrity
			- Tunneling
			- X11 Forwarding
- SFTP & FTPS
	- SFTP stands for SSH File Transfer Protocol and allows secure file transfer
		- Uses port number 22
		- Common commands:
			- sftp username@hostname
			- get filename
			- put filename
		- Easy to set up
	- FTPS stands for File Transfer Protocol Secure
		- Secured using TLS just like HTTPS
		- Uses port 990
		- Requires certificate setup and tricky to use with strict firewalls
