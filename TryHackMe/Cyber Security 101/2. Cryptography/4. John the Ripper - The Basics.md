- Basic Terms:
	- What are Hashes
		- A way to take a piece of data (any length) and represent it in another form of fixed length masking the original data
		- Hash value is obstained by running the original data through a hash algorithm
		- Common hashing methods: MD4, MD5, SHA1, HTLM
	- What Makes Hashes Secure
		- It's easy to create a hash value but find given a hash value to find the original data
		- Visualized as P x NP
			- - **P (Polynomial Time)**: Class P covers the problems whose solution can be found in polynomial time. Consider sorting a list in increasing order. The longer the list, the longer it would take to sort; however, the increase in time is not exponential.
			- **NP (Non-deterministic Polynomial Time)**: Problems in the class NP are those for which a given solution can be checked quickly, even though finding the solution itself might be hard. In fact, we don’t know if there is a fast algorithm to find the solution in the first place.
	- Where John Comes in
		- Cracking hashes is not impossible just time consuming and not feasibly reversable
			- If you have the hashed version of a password (secret thing) and know the hashing algorithm used (way you encrypted it) then you can use that hashing algorithm to hash a large number of words (aka dictionary)
				- Process is called a dictionary attack
				- Common tool: John the ripper (John) for conducting faste brute force attachs (supports various hash types)
					- Most popular extendsion version is "Jumbo John"

- Cracking Basic Hashes
	- John Basic Syntax
		- john `[options] [file path]`
			- john: Invokes the program
			- `[options]:` Specifies the options you want to use
			- `[file path]`: The file containing the hash you're targeting
	- Automatic Cracking
		- Has a built in feature to detech the type of hash
			- Not always right, can be unreliable
			- `john --wordlist=[path to wordlist] [path to file]`
				- `--wordlist`: Specifies using wordlist mode, reading from the file that you supply in the provided path
				- `[path to wordlist]`: The path to the wordlist you're using, as described in the previous task
	- Identifying Hashes
		- You can use an online hash identifier if the "automatic" mode doesn't work
			- Common tools:
				- https://hashes.com/en/tools/hash_identifier
				- https://gitlab.com/kalilinux/packages/hash-identifier/-/tree/kali/master
		- Hash-identifier is a python tool that is easy to  use and supports trying to determine different types of hashes
	- Format-Specific Cracking
		- how to tell John to use a certain format: `john --format=[format] --wordlist=[path to wordlist] [path to file]`
		- use `raw-` if dealing with a standard hash type (ex: md5)
		- list all formats: john --list=formats
		- use hash-identifier to find type of format to use if john doesnt pick it up
- Cracking Windows Authentication Hashes
	- NTHash/NTLM:
		- NThash is the hash format modern Windows systems use to Store user/service passwords
			- aka NTLM
			- NT stood for "New Technology" to separate it from the MS-DOS OS products
		- In Windows, SAM (Security Account Manager) is used to store user account info, including usernames/hashed passwords
- Cracking Hahes from /etc/shadow
	- `/etc/shadow` file is the file on Linux machines where password hashes are stored and is generally oncly accessible by root
	- Unshadowing
		- John can be very particular about the format of data to be able to work with it
			- Ex: To crack /etc/shadown passwords, you must combine it with the /etc/passwd file for John to understand the data using a tool called `unshadow`
			- ex syntax: `unshadow [path to passwd] [path to shadow]`
			- ex usage: `unshadow local_passwd local_shadow > unshadowed.txt`
	- Cracking
		- We can feed output from `unshadow` directly into John
- Single Crack Mode
	- Word Mangling
		- In `Single Crack Mode`, john uses only the info provided in the username to try and find possible passwords heuristically by slightly changing the letters/numbers contained in the username
			- Uses word mangling (word mutation)
	- GECOS
		- John's word mangling is compatible with GECOS field of the UNIX operating system (General Electric Comprehensive Operating System)
	- Using Single Crack Mode
		- Uses similar syntax
		- `john --single --format=[format] [path to file]`
- Custom Rules
	- Has ability to define your own rules from which John will use to create passwords dynamically
	- This pattern can let us exploit password complexity predictability
	- Common Custom Rules
		- Common in applications are password requirements to increase complexity
			- lowercase letter
			- uppercase letter
			- number
			- symbol
	- How to create Custom Rules
		- Defined in the `john.conf` file which is located in `/etc/john/john.conf`
	- To do a flag:
		- --rule=THMRules
- Cracking Password Protected Zip Files
	- John can be used to crack the password on password-protected Zip files
	- Zip2John
		- Similar to the `unshadow` tool, we can use the `zip2john` tool to conert the Zip file into a hash format that John can understand & crack
		- Format: `zip2john [options] [zip file] > [output file]`
	- Cracking
		- Once we use zip2john and get the output file we can feed it directly into John like this
			- Format: `john --wordlist=/usr/share/wordlists/rockyou.txt zip_hash.txt`
		- - **Crack ZIP → extract file:** Use John to find the ZIP password, then `unzip -P <password> file.zip` and `cat <file>` to retrieve the flag.
- Cracking Password-Protected RAR Archives
	- RAR archives are compressed files/folders created by the WinRAR archive manager
	- Rar2John
		- Almost identical to the `zip2john` we can use `rar2john` to convert the RAR file into a has format for John to understand
		- Format: `rar2john [rar file] > [output file]`
		- Example usage: `/opt/john/rar2john rarfile.rar > rar_hash.txt`
	- Cracking
		- Once you get the output from `rar2john` in a hash.txt form you feed it directly into john this way
			- Format: `john --wordlist=/usr/share/wordlists/rockyou.txt rar_hash.txt`
		- **Crack RAR → extract file:** Use John to crack the RAR password, then `unrar x -p<password> file.rar` and `cat <file>` to retrieve the flag.
- Cracking SSH Keys w/ John
	- Cracking SSH Key Passwords
		- We can also use John to crack the SSH private key password of `id_rsa` files
		- Background:
			- Unless configured differently, you authenticate your SSH login using a password. You can configure ke-based authetnication, which lets you use your private key (id_rsa) as an authentication key to login to the remote machine over SSH
				- John can crack this to allow authentication over SSH using the cracked key
	 - SSH2John
		 - Use `ssh2john` which converts the id_rsa private key into a hash format that John can work with
		 - Format: `ssh2john [id_rsa private key file] > [output file]`
		 - Example: `/opt/john/ssh2john.py id_rsa > id_rsa_hash.txt`
	- Cracking
		- Feed the file we outputted from `ssh2john` into john
		- Ex: `john --wordlist=/usr/share/wordlists/rockyou.txt id_rsa_hash.txt`
