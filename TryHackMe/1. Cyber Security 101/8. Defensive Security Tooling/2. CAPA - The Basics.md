- Introduction
	- Background
		- One risk of analyzing malicious software is the risk of our machine/environment being compromised when we run it unless we have a sandbox or completely isolated environment to test it
		- Two types of analysis
			- Dynamic analysis
			- Static analysis
				- CAPA is static
		- CAPA stands for "Common Analysis Platform for Artifacts" and was developed by the FireEye Mandiant team
		- It was designed to identify the capabilitites present in executable files like "Portable Executables (PE)", ELF binaries, .NET modules, shellcode, and even sandbox reports
			- It analyzes the file and applies a set of rules that describe common behaviors which allows it to determine what the program is capable of doing (ex: network communicaiton, file manipulation, process injection)
			- Encapsulates reverse engineering
		- The tool is mainly used in malware analysis and threat hunting
- Dissecting CAPA Results Part 1: General Information, MITRE,  and MAEC
	- MITRE ATT&CK (Adversarial Tactics, Techniques, and Common Knowledge) framework
		- It is a comprehensive global knowledge repo that documents the tactics and techniques used by threat actors in cyber attacks
		- Functions as a strategic playbook
	- MAEC
		- It is a specialized language designed to encode and communicate complex details concerning malware
		- Standardized system for tracking & analyzing the complexities of malware
		- Most common MAEC values used by CAPA 
			- Downloader: Exhibits behaviours wherein it downloads & executes other files
				- Tagged as downloader when it exhibits the following:
					- Fetching additional payloads or resources from the internet  
					- Pulling in updates
					- Executing secondary stages
					- Retrieving configuration files
			- Launcher: Exhibits behaviours that trigger specific actions similar to malware behaviour
				- Tagged as launcher when it exhibits the following:
					- Dropping additional payloads
					- Activating persistence mechanisms
					- Connecting to command-and-control (C2) servers
					- Executing specific functions
- Dissecting CAPA Results Part 2: Malware Behavior Catalogue
	- Malware Behavior Catalogue (MBC)
		- MBC is designed to support various aspects of malware analysis (labeling, similarity analysis, and standardized reporting)
			- It serves as a catlogue of malware objectives & behaviors
			- It can also link to ATT&CK methods and log all behaviors/code features discovered during malware analysis
	- Objective
		- The Objective are based on ATT&CK tactics in the context of malware behaviour, though not all are included. Furthermore, MBC has Anti-Behavioral and Anti-Static Analysis. These objectives are tailored for malware analysis with the use case of characterizing malware. See the table below for an explanation of each.
	- Micro-Objective
		-  Micro-objectives are associated with micro-behaviors, which refer to an action or actions exhibited by potentially malicious software that isn't necessarily malicious and may serve various objectives. Example binaries are such as those in messaging apps. However, it's important to **note that these behaviours are typically abused.**
	- Method
		- Methods are tied to behaviors; therefore, to fully see all methods, please refer to each specific behavior/micro behavior of interest.
- Dissecting CAPA Results Part 3: Namespaces
	- Namespaces
		- CAPA uses namespaces to group items with the same purpose
			- Ex: anti-analysis, collection, communication, compiler, data-manipulation, etc
