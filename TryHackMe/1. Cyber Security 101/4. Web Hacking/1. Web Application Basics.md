- HTTP Messages
	- HTTP message are just packets of data that are exchanged between the client and web server
		- Show users' requests and the server's responses
	- Two types
		- **HTTP Requests**: Sent by the user to trigger actions on the web application.
		- **HTTP Responses**: Sent by the server in response to the user’s request.
	- Anatomy of a HTTP Message
		- Start Line: 
			- introduction of message and tells you what kind of message is being sent and how it should be handled
		- Header: 
			- made up of key-value pairs that provide extra information about the HTTP message. They give instructions to the client/server handling the request/response. Headers can cover security/content types/etc.
		- Empty Line: 
			- A divider that separates the header & body for clarity of communication
		- Body:
			- Where the actual data is stored
	- Why Understanding HTTP Messages Matters
		- These messages are the foundation of how web applications communicate. If they’re structured properly, everything works smoothly.
		- Knowing how they work will help you diagnose issues in web communication, which means better performance and reliability for your web application.
		- It’s also crucial for security. Understanding HTTP messages helps you implement strong security measures to protect data during transmission.
