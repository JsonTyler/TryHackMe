- HTTP Messages
	- HTTP message are just packets of data that are exchanged between the client and web server
		- Show users' requests and the server's responses
	- Two types
		- **HTTP Requests**: Sent by the user to trigger actions on the web application.
		- **HTTP Responses**: Sent by the server in response to the user’s request.
	- Anatomy of a HTTP Message
		- Start Line: 
			- introduction of message and tells you what kind of message is being sent and how it should be handled
		- Header: 
			- made up of key-value pairs that provide extra information about the HTTP message. They give instructions to the client/server handling the request/response. Headers can cover security/content types/etc.
		- Empty Line: 
			- A divider that separates the header & body for clarity of communication
		- Body:
			- Where the actual data is stored
	- Why Understanding HTTP Messages Matters
		- These messages are the foundation of how web applications communicate. If they’re structured properly, everything works smoothly.
		- Knowing how they work will help you diagnose issues in web communication, which means better performance and reliability for your web application.
		- It’s also crucial for security. Understanding HTTP messages helps you implement strong security measures to protect data during transmission.
- HTTP Request: Request Line & Methods
	- Definition
		- An HTTP request is essentially what a user sends to a web server to interact with a web app
		- ![[Pasted image 20261003183131.png|306]]
	- Request Line:
		- First part of an HTTP request and tells the server the kind of request
		- 3 main parts:
			- HTTP method
			- URL path
			- HTTP version
	- Http Methods
		- Tells the server what kind of action you want to perfom on the resource identified by the URL path
		- GET, POST, PUT, DELETE, PATCH, HEAD, OPTIONS, TRACE, CONNECTION
		- Each of the above methods has it's own set of security rules
	- URL Path
		- Tells the server where to find the resource it's asking for
		- Common for attackers to try and manipulate the URL path to exploit vulnerabilityies
		- Important to:
			- Validate the URL path to prevent unauthorised access
			- Sanitise the path to avoid injection attacks
			- Protect sensitive data by conducting privacy and risk assessments
	- HTTP Version
		- Shows the protocol version used to communicate between the client & server
			- **HTTP/0.9** (1991)The first version, only supported GET requests.
			- **HTTP/1.0** (1996)Added headers and better support for different types of content, improving caching.
			- **HTTP/1.1** (1997): Brought persistent connections, chunked transfer encoding, and better caching. It’s still widely used today.
			- **HTTP/2** (2015): Introduced features like multiplexing, header compression, and prioritisation for faster performance.
			- **HTTP/3** (2022): Built on HTTP/2, but uses a new protocol (QUIC) for quicker and more secure connections
		- HTTP/2 & HTTP/3 offer better speed & security but many systems still use HTTP/1.1 because it's well supported and works in most setups
- HTTP Request: Headers & Body
	- Request Headers
		- They allow extra info to be sent to the web server
		- Common Request Headers
			- Host: Specifies the name of the web server the request is for.
			- User-Agent: Shares information about the web browser the request is coming from.
			- Referer: Indicates the URL from which the request came from.
			- Cookie: Information the web server previously asked the web browser to store is held in cookies.
			- Content-Type: Describes what type or format of data is in the request.
	- Request Body
		- The data is located inside the HTTP Request Body (POST/PUT)
		- Formatting of data can take many forms: URL Encoded, Form Data, JSON, XML
