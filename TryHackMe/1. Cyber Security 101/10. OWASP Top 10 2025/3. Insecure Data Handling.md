- A04: Cryptographic Failures
	- What is it
		- This happens when sensitive data isn't adequately protected due to lack of encryption, fauly implementation, or insufficient security measures
	- How to prevent
		- Starts with choosing strong/modern algorithms and using them properly
		- Sensitive info such as passwords should be hashed properly
		- Never embed access credentials in source code/config files/repos
		- Use secure key management systems
- A05: Injection
	- What is it
		- Classic example of web exploitation
		- High severity
		- This happens when an application takes user input and mishandles it
			- Instead of processing the input securely it passes it directly into a system that can execute commands/queries 
		- Examples:
			- SQL Injection
			- Command Injection
			- AI Prompts
			- Server Side Template Injection (SSTI)
	- How to prevent
		- Starts by ensuring that user input is always treated as untrusted
		- Input validation & sanitization are important to help prevent
- A08: Software or Data Integrity Failures
	- What is it
		- This happens when an application relies on code/updates/data it assumes as safe without verifying authenticity/integrity/origin
	- How to avoid
		- Starts with establishing trust boundaries
		- Apps should never assume code/updates/data are legit & should never be automatically trusted until integrity is verified via cryptographic checks (checksums)
