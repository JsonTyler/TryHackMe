- Introduction
	- Shells are widely used in cybersecurity by attackers to remotely control systems
- Shell Overview
	- What is a Shell
		- A software that allows a user to interact with an Operating System
			- It can be a GUI, but is most commonly a CLI
	- Shell when referring to an attack can be refering a session doing:
		- - **Remote System Control**: allows the attacker to execute commands or software remotely in the target system.
		- **Privilege Escalation**: If initial access through a shell is limited or restricted, attackers can explore ways to escalate privileges to more elevated or administrative access.
		- **Data Exfiltration**: Once attackers have access to execute commands through an obtained shell, they can explore the system to read and copy sensitive data from it.
		- **Persistence and Maintenance Access**: Once shell access is obtained, attackers can create access through users and credentials or copy backdoor software to maintain access to the target system for later usage.
		- **Post-Exploitation Activities**: After access to a shell is granted, attackers can perform a wide range of post-exploitation activities, such as deploying malware, creating hidden accounts, and deleting information.
		- **Access Other Systems on the Network**: Depending on the attacker's intentions, the obtained shell can be just an initial access point. The goal can be to hop through the network to a different target using the obtained shell as a pivot to different points in the compromised system network. This is also known as pivoting.
- Reverse Shell
	- Background
		- A reverse shell (aka connect back shell) is one of the most popular techniques for gaining access to a system in cyberattacks
		- The connections initiate from the target system to the attackers's machine (helps avoid detection)
- Bind Shell
	- Background:
		- A bind shell will bind a port on the compromised system and listen for a connection. Then when the connection occurs it exposes the shell session so the attacker can execute commands remotely
			- Good because:
				- It can be used when the compromised target does not allow outgoing connections
			- Bad because:
				- Needs to remain active and listen for connections which can lead to detection
	- Note:
		- Listening below port 1024 will require root access/privileged permissions and should be avoided
- Shell Listeners
	- Previously in tasks above we saw that a reverse shell will connect from the compromised target to the attacker's machine
		- A tool like Netcat will handle the connection and allow for interaction with the exposed shell, but there are more than just Netcat
	- Others
		- Rlwrap: A small utility that uses the GNU readline library to provide editing keyboard and history
		- Ncat: An improved version of Netcat distributed by the NMAP project (extra features, like encryption [--ssl for SSL encryption])
		- Socat: A utility that allows you to create a socket connection between two data sources (different hosts)
- Shell Payloads
	- Can be a command/script that exposes the shell to an incoming connection (for bind shell) or send a connection (reverese shell)
	- A **shell payload** is a command or script that gives an attacker shell access over a network. It can be used with either a **reverse shell** or **bind shell**.
		- **Reverse shell:** Target connects back to the attacker.
		- **Bind shell:** Target opens a listening port, and the attacker connects to it.
		- Payloads vary depending on what tools/languages are available on the target.
		- Common payload options include **Bash, Python, PHP, Netcat**, etc.
		- For Bash, `/dev/tcp/IP/PORT` can create a TCP connection without requiring Netcat.
		- The attacker needs a **listener** running to receive a reverse-shell connection.
	- **Main takeaway:** **Listener = waits for the connection. Payload = creates the shell connection.**
	- Notes
		- Which scripting language can use a reverse shell by exporting env variables and creating a socket connection --> python
		- What python module is commonly used for managing shell commands and establishing reverse shell connections in security assessments --> subprocess
- Web Shell
	- Background
		- A web shell is a script written in a language supported by a compromised web server that executes commands through the web-server itself
		- A web shell is usually a file containing the code that executes commands and handles files
		- The web shell can be hidden within a compromised web app/service
		- Web shells can be written in many different language: PHP, ASP, JSP, CGI, etc
	- Various web shells: [https://www.r57shell.net/index.php (opens in new tab)](https://www.r57shell.net/index.php).
	- What can happen
		- The above shell can be saved into a file with the PHP extension, like `shell.php`, and then uploaded into the web server by the attacker by exploiting vulnerabilities such as [Unrestricted File Upload](https://tryhackme.com/r/room/uploadvulns), [File Inclusion](https://tryhackme.com/r/room/fileinc), [Command Injection](https://tryhackme.com/r/room/oscommandinjection), among others, or by gaining unauthorized access to it.
