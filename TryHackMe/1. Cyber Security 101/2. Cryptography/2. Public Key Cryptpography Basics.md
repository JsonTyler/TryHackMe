- Introduction
	- Vocab:
		- Authentication: You want to be sure you communicate with the right person, not someone else pretending
		- Authenticity: You can verify that the information comes from the claimed source
		- Integrity: You must ensure that no one changes the data you exchange
		- Confidentiality: You want to prevent an unahtorized party from eavesdropping on your conversations
	- Cryptography does all of the above
- RSA
	- RSA  is a public-key encryption algorithm that enables secure data transmission over insecure channels
	- Based on the mathematically difficult problem of factoring a large number![[Pasted image 20260928191353.png]]
	- Understanding ϕ(n)
		- ϕ(n) = n - p - q + 1
		- Remember n = p x q
- Diffie-Hellman Key Exchange
	- One of the challenges of using symeetric encryption is sharing the secret key, best iif you have  a secure channel
	- Key exchange: aims to establish a shared secret between two parties
		- A method that allows 2 parties to establish a shared secret over an insecure communication channel without requiring a pre-existing shared secret and w/o an observer being able to get this key![[Pasted image 20260928192703.png]]
	- Diffie-Hellman Key Exchange is often u sed alongside RSA public key cryptography
		- Diffie-Hellman is used for key aggreement
		- RSA is used for digital signatures, key transport, and authentication
	- Both Diffie-Hellman & RSA are incorporated into many security protocols & standards
- SSH
	- Authenticating the Server
		- SSH client confirms on login whether we recognize the sever's public key fingerprint used for digital signature generation and verification
		- This occurs when the SSH client doesn't recognize the key and asks us to cofnfirm whether we sitll want to connect
		- Occurs because man-in-the-middle attack can happen where a malicious server may intercept the connection and replies, pretending to be the target server
	- Authenticating the Client
		- After confirming that we are talking with the correct server we need to be authenticated
		- SSH users most commonly are authenticated with usernames & passwords
			- key authentication can also be used (uses public & private keys to prove the client is a valid/authorized user on the server)
			- By default SSH keys are RSA keys
			- `ssh-keygen` is the prorgram usually used to generate key pairs (supports various algorithms)
		- Types of keys available
			- - **DSA (Digital Signature Algorithm)** is a public-key cryptography algorithm specifically designed for digital signatures.
			- **ECDSA (Elliptic Curve Digital Signature Algorithm)** is a variant of DSA that uses elliptic curve cryptography to provide smaller key sizes for equivalent security.
			- **ECDSA-SK (ECDSA with Security Key)** is an extension of ECDSA. It incorporates hardware-based security keys for enhanced private key protection.
			- **Ed25519** is a public-key signature system using EdDSA (Edwards-curve Digital Signature Algorithm) with Curve25519.
			- **Ed25519-SK (Ed25519 with Security Key)** is a variant of Ed25519. Similar to ECDSA-SK, it uses a hardware-based security key for improved private key protection.
		- SSH Private Keys
			- Private ssh keys should be treated like passwords (never share)
			- Keys Trusted by the Remote Host
				- The `~/.ssh` folder is the default place to store these keys for OpenSSH
				- The `authorized_keys` are allowed access to the server if key authentication is enabled
				- By default on many Linux distros, key authentication is enabled
				- Only key authentication should be accepted if you want to allow SSH access for the root user
- DIgital Signatures & Certificates
	- What's a Digital Signature
		- Digital signatures provide a way to verify the authenticity/integrity of a digital message or documnet
			- Allows us to know who created/modified it
			- Simplest form of a digital signature is encrypting the document with your private key. If someone wants to verify it, they decrypt it with your public key to check if the files match![[Pasted image 20260928195641.png]]
	- Certificates: Prove Who You Are!
		- Linked to digital signatures and essential part of public key cryptography
		- Commonly used in HTTPS
			- The web server has a cert that says it's the real site
		- Let's Encrypt is used to get a free TLS certificate for websites
		- Certificates are used by remote web servers to prove themselves to the client
- PGP & GPG
	- PGP stands for "Pretty Good Privacy"
		- It's software that implements encryption for encrypting files, performing digital signing, etc
		- GnuPG or GPG is an open-source implementation of the OpenPGP standard
	- GPG is commonly used in email to protect confidentiality
		- Can also be used to sign an email message to confirm it's integrity
	- Practical Example
		- gpg --import backup.key (imports keys from backup.key)
		- gpg --decrypt confidential_message.gpg (to descrypt messages)
- Conclusion
	- Vocab:
		- **Cryptography** is the science of securing communication and data using codes and ciphers.
		- **Cryptanalysis** is the study of methods to break or bypass cryptographic security systems without knowing the key.
		- **Brute-Force Attack** is an attack method that involves trying every possible key or password to decrypt a message.
		- **Dictionary Attack** is an attack method where the attacker tries dictionary words or combinations of them.
