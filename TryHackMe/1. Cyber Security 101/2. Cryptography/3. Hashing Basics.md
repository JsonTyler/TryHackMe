- Introduction
	- Issue: How to verify authenticity/integrity that a file is what you think it is
	- Solution: Compare the hash values of the file you have vs the one you expect
	- Vocab:
		- Hash value: a fixed-size string or characters that is computed by a hash function
		- Hash function: takes an input of an arbitrary size and returns an output of fixed length (ex: a hash value)
- Hash Functions
	- What is a Hash Function:
		- Hash functions are different from encryption in that there is no key
		- A hash function takes some input data of any size and creates a summary/digest of that data
		- Good hashing algorithms are fast to compute and prohibitively slow to reverse
		- The output of a hash function is generally in raw byes, which are then encoded
		- Common encodings:
			- base64 & hexadecimal
			- md5sum, sha1sum, sha256sum, and sha512sum produce their outputs in hexadecimal format
	- Why is Hashing Important?
		- Hashing helps protect data's integrity and ensure password confidentiality
	- What's a Hash Collision?
		- A hash collision is when two different inputs give the same ouput
		- Hash functions are designed to avoid collisions as best as possible
		- The `pigeonhole effect` states that the number of items (pigeons) is more than the number of containers `pigeonholes`; some containers must hold more than one item
			- Plainly: There are a fixed number of different outputs values for the hash function but you can give it any size input. As there are more inputs than outputs, some inputs must inevitable give the same output
			- Collisions are unavoidable but a good hash function can ensure the probability of a collision is minimal
- Insecure Password Storage for Authentication
	- 3 insecure practices for password storage
		- Storing passwords in plaintext
		- Using an insecure encryption algorithm
		- Using an insecure hash function
- Using Hashing for Secure Password Storage
	- Using Hasing to Store Passwords
		- Instead of storing passwords you could just store the hash value using a secure hashing function
			- Problem: 
				- if two users have the same password then cracking that hash the hacker will gain access to multiple accounts
				- someone can create a Rainbow Table to break the hashes
		- Rainbow Table: is a lookup table of hashes to plaintexts so one can quickly find out the password form the hash
			- Trades the time to crack a hash for hard disk space (takes time to create)
	- Protecting Against Rainbox Tables
		- To protect against them we add a `salt` to our passwords
		- Salt is a randomly generated value stored in the db and unique to each user
			- Added to start or end of the password before it's hashed
	- Using Encryption to Store Passwords
		- The reason we don't encrypt passwords is that even if we encrypt we sill need to store the key which defeats the purpose
	- Online tools:
		- https://hashes.com/en/decrypt/hash
		- https://crackstation.net/
- Recognizing Password hashes
	- Linux Passwords
		- Password hashes are stored in `/etc/shadow` normally only readable by root
	- MS Windows Passwords
		- Passwords hashed using NTLM a variant of MD4
		- Stored in the SAM (Security Accounts Manager)
- Password Cracking
	- One can use rainbow tables as a method to crack hashes that don't use a salt
	- You can't decrypt password hashes as they are not encrypted
	- To crack a hash that uses a salt you have to use hashing many different inputs and comparing it to the target hash.....until it matches and then you know the password
		- Tools like hashcat and john the ripper are used for this
	- Cracking Passwords with GPUs
		- You can use a graphics card to crack many hash types quickly. Some hashing algorithms, such as Bcrypt, are designed so that hashing on a GPU does not provide any speed improvement over using a CPU; this helps them resist cracking
	- Cracking on VMs
		- VMs (Lab Machines) normally don’t have access to the host’s graphics card(s). Furthermore, performance degradation occurs as you use the CPU from a virtualised OS, and when your purpose is to crack a hash, you need every extra CPU cycle.
		- Tools you can use are Hashcat or John the Ripper (uses CPU by default and works in a VM out of the box)
